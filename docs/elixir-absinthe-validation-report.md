# Elixir Absinthe Live Validation Report

## Scope

This report records the third blind Elixir live-repository pass and the difficult project/command-ownership role. The candidate was selected before inspecting its audit output: [`absinthe-graphql/absinthe`](https://github.com/absinthe-graphql/absinthe) at exact commit [`de0e411f3ca4f31ad8cf5e31921c735aa3b0f986`](https://github.com/absinthe-graphql/absinthe/commit/de0e411f3ca4f31ad8cf5e31921c735aa3b0f986).

Absinthe is a macro-heavy GraphQL toolkit with 265 production Elixir files and 230 `*_test.exs` files. It keeps one root Mix application, compiles support modules only in the test environment, wraps ExUnit through local `__using__/1` macros, ships conventional Mix tasks, preserves acronym namespaces, and conditionally repeats exact module declarations for optional runtime features.

## Bounded Correction

The adapter now recognizes `test/support` only when `mix.exs` both wires `elixirc_paths(Mix.env())` into the project and declares a literal `elixirc_paths(:test)` list containing `test/support`. Within that owned root it resolves exact app-owned support modules whose single `__using__/1` body contains either `use ExUnit.Case` or one already resolved local wrapper. Dynamic compile paths, unrelated support modules, multiple framework uses, and arbitrary macro expansion remain rejected.

Standard `lib/mix/tasks/**/*.ex` and matching `test/mix/tasks/**/*_test.exs` paths may own exact `Mix.Tasks.*` modules outside the application namespace. A source file may also own repeated declarations only when every conventional match has the same exact FQN, while different normalized declarations remain a collision. Finally, a snake-case terminal may map to one additional declared namespace segment only when that segment is an all-uppercase acronym and concatenating the final two declared segments exactly matches the conventional terminal. This covers `sdl_render` to `SDL.Render` without treating arbitrary path segments as interchangeable namespaces.

These rules establish test and source ownership only. They do not infer code generated by `use Absinthe.Schema`, imports supplied by local wrappers, setup/helper reachability, GraphQL execution reachability, optional dependency branches, or other macro-expanded behavior as direct coverage.
